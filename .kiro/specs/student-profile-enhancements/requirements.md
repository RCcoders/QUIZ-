# Requirements Document

## Introduction

This feature enhances the student experience in QuizMaster by adding four interconnected capabilities:

1. **Badges System** — Award visual badges to students based on measurable achievements (streaks, quiz scores, improvement milestones). Badges are stored in Firestore and displayed on the student profile and dashboard.
2. **Student Library / Notes Section** — A structured learning area where students can read teacher-published notes/materials organized by subject, then practice with quizzes linked to that content.
3. **AI-Based Adaptive Quiz System** — Practice quizzes powered by Gemini AI that adjust question difficulty based on the student's recent performance history, targeting weak areas and reinforcing strengths.
4. **Settings & Profile Section** — Profile editing and account preferences for both student and teacher roles, including display name, avatar, notification preferences, and password management.

The system builds on the existing `UserProfile`, `ScoreRecord`, Firestore backend, `AuthContext`, and Gemini AI integration (`src/lib/gemini.ts`).

---

## Glossary

- **Badge_Engine**: The subsystem responsible for evaluating badge award conditions and writing badge records to Firestore.
- **Badge**: A named, visual achievement awarded to a student when a defined condition is met.
- **Student_Library**: The student-facing page that lists learning materials (notes) organized by subject.
- **Note**: A teacher-published learning material document containing text content and an optional linked quiz.
- **Adaptive_Quiz**: A quiz session whose question set is generated by the AI_Service based on the student's performance profile.
- **AI_Service**: The Gemini-backed service (`src/lib/gemini.ts`) extended to support adaptive question generation.
- **Performance_Profile**: A derived summary of a student's `ScoreRecord` history used as input to the AI_Service for adaptive quiz generation.
- **Profile_Editor**: The UI component that allows a user to update their display name, avatar URL, and preferences.
- **Settings_Page**: The page accessible to both student and teacher roles for managing account settings.
- **Firestore**: The Firebase/Firestore database used as the persistence layer.
- **AuthContext**: The existing React context providing the authenticated user and `UserProfile`.
- **StudentNavbar**: The existing top navigation component for student pages.
- **TeacherSidebar**: The existing sidebar navigation component for teacher pages.

## Requirements

### Requirement 1: Badge Award Engine

**User Story:** As a student, I want to earn badges for my achievements, so that I feel motivated and can see my progress at a glance.

#### Acceptance Criteria

1. THE Badge_Engine SHALL define at least the following badge types: `first_quiz` (complete first quiz), `streak_3` (3-day streak), `streak_7` (7-day streak), `perfect_score` (100% on any quiz), `high_achiever` (average score ≥ 80% over 10+ quizzes), `improvement` (score improves by ≥ 20 percentage points on the same quiz retaken).
2. WHEN a student completes a quiz, THE Badge_Engine SHALL evaluate all badge conditions against the student's updated `ScoreRecord` history within 5 seconds of quiz completion.
3. WHEN a badge condition is met for the first time, THE Badge_Engine SHALL write a badge record to the `users/{uid}/badges` Firestore subcollection containing: `badgeId`, `awardedAt` (ISO timestamp), and `quizId` (if applicable).
4. THE Badge_Engine SHALL award each badge type to a given student at most once (idempotent award).
5. IF a Firestore write fails during badge award, THEN THE Badge_Engine SHALL retry the write up to 3 times before logging the error and continuing without blocking the quiz completion flow.

---

### Requirement 2: Badge Display on Student Dashboard

**User Story:** As a student, I want to see my earned badges on my dashboard, so that I can track my achievements.

#### Acceptance Criteria

1. THE StudentDashboard SHALL display a "My Badges" section showing all badges earned by the authenticated student, fetched from `users/{uid}/badges`.
2. WHEN a student has earned zero badges, THE StudentDashboard SHALL display an empty-state message encouraging the student to complete quizzes to earn their first badge.
3. WHEN a new badge is awarded during the current session, THE StudentDashboard SHALL display a toast notification with the badge name and description within 3 seconds of the award.
4. THE StudentDashboard SHALL render each badge with its icon, name, and award date.
5. WHILE badge data is loading from Firestore, THE StudentDashboard SHALL display a loading skeleton in place of the badges section.

---

### Requirement 3: Student Library — Browse Notes

**User Story:** As a student, I want to browse learning materials organized by subject, so that I can study content before taking a related quiz.

#### Acceptance Criteria

1. THE Student_Library SHALL be accessible at the route `/student/library` and linked from the StudentNavbar.
2. THE Student_Library SHALL fetch and display all `Note` documents from the `notes` Firestore collection where `published` is `true`.
3. THE Student_Library SHALL support filtering notes by subject using subject chips, consistent with the existing Library component pattern.
4. THE Student_Library SHALL support full-text search across note `title` and `subject` fields (client-side filtering).
5. WHEN a student selects a note, THE Student_Library SHALL navigate to a note detail page at `/student/library/:noteId` displaying the full note content.
6. WHILE notes are loading from Firestore, THE Student_Library SHALL display a loading skeleton.
7. IF no notes match the active filter or search query, THEN THE Student_Library SHALL display an empty-state message.

---

### Requirement 4: Student Library — Note Detail and Linked Quiz

**User Story:** As a student, I want to read a note and then immediately practice with a linked quiz, so that I can reinforce what I just learned.

#### Acceptance Criteria

1. THE Note detail page SHALL display the note's `title`, `subject`, `content` (rendered as formatted text), and `createdAt` date.
2. WHERE a `Note` has a `linkedQuizId` field, THE Note detail page SHALL display a "Practice Quiz" button that navigates to `/student/quiz/:linkedQuizId`.
3. WHERE a `Note` has no `linkedQuizId`, THE Note detail page SHALL display an "Adaptive Practice" button that navigates to `/student/adaptive-quiz?noteId=:noteId`.
4. THE Note detail page SHALL display a breadcrumb navigation back to the Student_Library.
5. IF the requested `noteId` does not exist in Firestore, THEN THE Note detail page SHALL display a "Note not found" error message and a link back to the Student_Library.

---

### Requirement 5: Teacher — Publish Notes to Library

**User Story:** As a teacher, I want to publish notes and learning materials to the student library, so that my students have structured content to study.

#### Acceptance Criteria

1. THE TeacherSidebar SHALL include a "Library" navigation item linking to `/teacher/library` (this route already exists; the requirement is to extend it with note management).
2. THE teacher library page SHALL display a list of the authenticated teacher's notes fetched from the `notes` Firestore collection filtered by `authorUid`.
3. WHEN a teacher submits a new note form with `title`, `subject`, `content`, and optional `linkedQuizId`, THE teacher library page SHALL write a new `Note` document to the `notes` Firestore collection with `published: false` by default.
4. WHEN a teacher toggles a note's published state, THE teacher library page SHALL update the `published` field on the corresponding Firestore document.
5. IF a note form is submitted with an empty `title` or empty `content`, THEN THE teacher library page SHALL display a validation error and SHALL NOT write to Firestore.

---

### Requirement 6: AI-Based Adaptive Quiz Generation

**User Story:** As a student, I want to take a practice quiz that adapts to my weak areas, so that I can improve efficiently.

#### Acceptance Criteria

1. THE AI_Service SHALL accept a `Performance_Profile` (subject, recent scores, weak topics derived from incorrect answers) and a `noteId` or `subject` as input, and SHALL return a set of questions targeting the student's identified weak areas.
2. WHEN a student initiates an adaptive quiz, THE AI_Service SHALL generate between 5 and 20 questions using the Gemini API, with difficulty distribution weighted toward the student's weakest-performing difficulty tier.
3. THE Adaptive_Quiz page SHALL be accessible at `/student/adaptive-quiz` and SHALL accept `noteId` or `subject` as query parameters.
4. WHEN the Adaptive_Quiz page loads, THE Adaptive_Quiz page SHALL display a loading state while the AI_Service generates questions, with a timeout of 15 seconds.
5. IF the AI_Service fails to generate questions within 15 seconds or returns an error, THEN THE Adaptive_Quiz page SHALL display an error message and offer a "Try Again" button and a fallback link to browse standard quizzes.
6. WHEN a student completes an adaptive quiz, THE Adaptive_Quiz page SHALL save the results as a `ScoreRecord` to `users/{uid}/scores` in Firestore, consistent with the existing scoring pattern.
7. FOR ALL adaptive quiz sessions, the question set generated for the same student and same subject on the same day SHALL vary by at least 30% from the previous session's questions (non-idempotent generation to ensure variety).

---

### Requirement 7: Adaptive Quiz Performance Feedback

**User Story:** As a student, I want to see targeted feedback after an adaptive quiz, so that I know exactly what to study next.

#### Acceptance Criteria

1. WHEN an adaptive quiz is completed, THE Adaptive_Quiz page SHALL display a results summary showing: total score, percentage, per-question correctness, and the correct answer for each incorrect response.
2. THE results summary SHALL identify the top 2 topics where the student answered incorrectly and display a "Study this topic" link to the relevant note in the Student_Library if a matching note exists.
3. WHEN a student scores below 60% on an adaptive quiz, THE Adaptive_Quiz page SHALL display a motivational message and a "Retry" button that generates a new adaptive quiz for the same subject.

---

### Requirement 8: Student Profile & Settings Page

**User Story:** As a student, I want to edit my profile and manage my account settings, so that my information is accurate and my preferences are saved.

#### Acceptance Criteria

1. THE Settings_Page SHALL be accessible at `/student/settings` and linked from the StudentNavbar (via the user avatar/initials menu).
2. THE Profile_Editor SHALL allow the authenticated student to update their `displayName` (1–50 characters) and `avatarUrl` (valid URL or empty string).
3. WHEN a student submits valid profile changes, THE Profile_Editor SHALL update the Firebase Auth profile via `updateProfile` and write the updated fields to the `users/{uid}` Firestore document, then display a success confirmation.
4. IF a student submits a `displayName` that is empty or exceeds 50 characters, THEN THE Profile_Editor SHALL display a validation error and SHALL NOT call Firebase.
5. THE Settings_Page SHALL include a "Change Password" section that allows the student to update their password by providing their current password and a new password (minimum 8 characters).
6. WHEN a student submits a valid password change, THE Settings_Page SHALL call Firebase Auth `reauthenticateWithCredential` followed by `updatePassword`, then display a success confirmation.
7. IF the current password provided is incorrect, THEN THE Settings_Page SHALL display an "Incorrect current password" error.
8. THE Settings_Page SHALL include a "Notification Preferences" section with a toggle for "Email me when a new quiz is published in my subjects". THE Settings_Page SHALL persist this preference to the `users/{uid}` Firestore document.

---

### Requirement 9: Teacher Profile & Settings Page

**User Story:** As a teacher, I want to edit my profile and manage my account settings, so that my information is accurate.

#### Acceptance Criteria

1. THE Settings_Page SHALL be accessible at `/teacher/settings` and linked from the TeacherSidebar.
2. THE Profile_Editor SHALL allow the authenticated teacher to update their `displayName` (1–50 characters) and `avatarUrl` (valid URL or empty string), with the same validation rules as Requirement 8.
3. WHEN a teacher submits valid profile changes, THE Profile_Editor SHALL update Firebase Auth and Firestore identically to the student flow (Requirement 8, criterion 3).
4. THE teacher Settings_Page SHALL include the same "Change Password" section as the student Settings_Page (Requirement 8, criteria 5–7).
5. THE teacher Settings_Page SHALL include a "Class Preferences" section with a text field for `defaultSubject` (the teacher's primary subject, max 50 characters). THE Settings_Page SHALL persist this to the `users/{uid}` Firestore document.

---

### Requirement 10: Firestore Data Model Extensions

**User Story:** As a developer, I want well-defined Firestore collections for the new features, so that data is consistent and queryable.

#### Acceptance Criteria

1. THE Firestore database SHALL support a `notes` collection with documents containing: `id`, `title` (string), `subject` (string), `content` (string), `authorUid` (string), `linkedQuizId` (string | null), `published` (boolean), `createdAt` (ISO timestamp), `updatedAt` (ISO timestamp).
2. THE Firestore database SHALL support a `users/{uid}/badges` subcollection with documents containing: `badgeId` (string), `awardedAt` (ISO timestamp), `quizId` (string | null).
3. THE Firestore database SHALL support a `users/{uid}` document extended with: `avatarUrl` (string | null), `notificationPrefs` (object), `defaultSubject` (string | null, teacher only).
4. THE firestore.rules file SHALL enforce that only the authenticated user with matching `uid` can write to their own `users/{uid}` document and `users/{uid}/badges` subcollection.
5. THE firestore.rules file SHALL enforce that `notes` documents can be read by any authenticated user, but can only be written by the `authorUid` matching the authenticated user's uid.
